## Problèmes rencontrés et solutions
- **Règle ESLint `react-refresh/only-export-components`** : `export *` et les exports non composants (animation, hooks, constantes) dans `v6.tsx` étaient refusés. Correctif : `v6Nav.ts` (fonctions/constantes), `v6Feedback.ts` (hooks), exports explicites dans `index.tsx`.
- **Inférence de type de `V6Segment`** : `T` était inféré à `string`, ce qui rejetait les setters d'état typés. Correctif : `NoInfer<T>` sur `options` et `onChange`. Même session : `onChange` de `V6InputItem` entrait en conflit avec celui d'`IonInput` → `Omit<…, 'onChange'>`.
- **`today.pw.ts` échouait déjà avant les changements** (vérifié en relançant le test sur le code d'origine via `git stash`) : `.v5-loading` puis `ion-refresher` trouvaient aussi les éléments de l'onglet Carnets resté monté (son API n'est pas simulée dans ce test). Correctif : sélecteurs limités à `.today-page` et `ion-content:has(.today-page)`.
- **Liste inset avec marge de 16 px** : la règle scoped d'Ionic `.list-ios.list-inset` l'emportait. Correctif : sélecteur plus spécifique `.v6-list-group ion-list.v6-list`.
- **Message d'erreur des champs invisible** : `ion-input` est un composant *scoped* (pas de shadow DOM), donc `::part()` ne s'applique pas, et j'avais mis `--highlight-color-invalid: transparent`, couleur utilisée par le texte d'erreur. Correctif : styles sur les classes internes (`.label-text-wrapper`, `.error-text`, `.helper-text`, `.input-bottom`) et texte d'erreur en encre avec ⚠︎. Vérifié par capture.
- **Feuille au fond Paragon sombre** : la règle globale qui pose le fond Paragon sur tout `.ion-page` touchait aussi l'enveloppe interne d'`ion-modal`. Correctif : `ion-modal.v6-sheet .ion-page { background: transparent }`. Vérifié par capture.
- **Hauteur de la barre d'onglets** : `ion-tab-bar` est en `box-sizing: content-box` et ajoute déjà la zone de sécurité basse ; mon `height: calc(49px + safe-area)` l'aurait comptée deux fois. Corrigé avant le push (`height: 49px`) ; vérifié avec `--ion-safe-area-bottom: 34px` simulé (barre de 84 px de haut = 49 + 34 + filet).
- **Sur iPhone, lignes glissables et crans de feuille ne réagissaient pas au doigt** (retour de Damien après déploiement). Dans Chromium avec tactile simulé par CDP, tout fonctionnait : glissement court → ligne ouverte à 88 px, glissement complet → feuille d'actions, poignée tirée → cran 0,5 → 1. Le problème est donc propre à Safari iOS.
  - **Cause retenue (non vérifiée sur appareil)** : `touch-action: pan-x pan-y` posé sur `html`/`body`/`#root` pour bloquer le zoom, qui remplace le `touch-action: manipulation` qu'Ionic pose sur `body`. Ce sont les premiers gestes JS d'Ionic utilisés dans l'app (le « tirer pour rafraîchir » iOS est natif, le retour par glissement est désactivé), d'où l'absence d'indice auparavant. Retirer ce réglage dans Chromium ne changeait rien (le bug n'y existe pas), donc l'hypothèse n'a pas pu être confirmée dans le cloud.
  - **Correctif** : retour à `manipulation` (le double-tap reste bloqué ; le pincement reste refusé par l'écoute `gesturestart` de `main.tsx`) ; flou d'arrière-plan retiré des éléments qui bougent sous le doigt (coût de rendu à chaque image sous Safari) ; `handleBehavior="cycle"` sur la feuille comme solution de repli et comportement iOS.
- **Toasts introuvables pour Damien** : les boutons « Toast succès / erreur » utilisaient un jargon. Correctif : boutons « Bandeau succès / Bandeau erreur », consignes sous chaque section, toast aussi déclenché par les interrupteurs.
- **`no-irregular-whitespace`** : les espaces insécables littérales autour des guillemets français étaient refusées par ESLint. Correctif : entités `&nbsp;` dans le JSX.

## Apprentissages
→ 05-Apprentissages
- **`touch-action` sur `html`/`body` et gestes Ionic** : Ionic pose `touch-action: manipulation` sur `body`, et ses gestes JS (`IonItemSliding`, crans d'`IonModal`) sont testés avec cette valeur. Remplacer cette valeur sur toute la page (ici `pan-x pan-y` pour bloquer le zoom) est un suspect sérieux quand ces gestes marchent dans Chromium mais pas sur iPhone. Pour bloquer le zoom sans y toucher : `manipulation` (double-tap) + `preventDefault` sur `gesturestart` (pincement, propre à Safari).
- **Valider un geste avec un vrai glissé, pas avec l'API** : la première validation ouvrait les lignes par `ionItemSliding.open()`, ce qui ne prouve rien sur le geste. Un glissé tactile simulé (CDP `Input.dispatchTouchEvent`) ou un glissé souris (accepté par les gestes Ionic, donc utilisable aussi en WebKit) teste réellement l'interaction.
- **Composants Ionic *scoped* contre *shadow*** : `ion-input`, `ion-action-sheet`, `ion-list` sont scoped (styles par classes internes, `::part()` inopérant) ; `ion-toggle`, `ion-segment-button`, `ion-toast`, `ion-modal` exposent des `::part()`. Vérifier avant de styler.
- **`--highlight-color-invalid` colore aussi le texte d'erreur d'`ion-input`** : le mettre à `transparent` rend le message invisible.
- **`ion-tab-bar` est en `content-box`** et ajoute lui-même `--ion-safe-area-bottom` : ne pas inclure la zone de sécurité dans sa hauteur.
- **`IonTabs` accepte une barre d'onglets enveloppée dans un composant** (détection par contexte), mais `IonTabBar` doit recevoir des `IonTabButton` comme enfants directs.
- **Accélérer les transitions Ionic** : `setupIonicReact({ navAnimation })` avec `iosTransitionAnimation(baseEl, { ...opts, duration: 350 })` garde la courbe et le décalage iOS.
- **Grand titre iOS sans restructurer les pages** : barre `position: sticky` + bloc titre comme deux enfants du conteneur qui défile ; une marge négative égale au `gap` du conteneur colle le titre sous la barre.
- **Une règle globale sur `.ion-page` touche aussi l'intérieur des modales** (enveloppe `.ion-page` d'`ion-modal`).
