## Problèmes rencontrés et solutions
- **Retrait d'une série ou d'un exercice non enregistré** : `UpdateAsync` faisait `_context.WorkoutSessions.Update(entity)` sur le graphe envoyé ; EF ne supprime pas les enfants absents du graphe. Correctif : suppression explicite des exercices et séries absents. Vérifié par `WorkoutEditTests` : 2 des 3 tests échouent sans le correctif (76/78), tous passent avec (78/78).
- **Brouillon perdu juste après une saisie** (trouvé par le test e2e « nouvelle séance » : après rechargement, le brouillon repris datait d'avant les dernières modifications) : écriture différée de 400 ms, relancée à chaque modification, donc rien n'était écrit si la page se fermait dans ce délai. Correctif : écriture immédiate de la valeur en attente sur `visibilitychange` (caché), `pagehide` et au démontage. Test vert ensuite.
- **Libellés de retour tronqués au repos** (« Carn… », « Histori… », « Séan… ») : le petit titre caché (opacité 0) occupait toujours sa largeur dans la grille de la barre, ce qui réduisait les colonnes latérales. Correctif : `max-width: 0` sur le petit titre quand la barre n'est pas repliée. Vérifié sur captures.
- **Éditeur 21 plus large que l'écran** : une pastille au texte `nowrap` élargissait la piste implicite de la grille `.history-page`. Correctif : `grid-template-columns: minmax(0, 1fr)` (aussi sur `.programs-page`). Vérifié sur captures.
- **Croix d'effacement visibles sur des champs non actifs** : `V6InputItem` forçait `clearInput`. Correctif : masquées hors focus (`.has-focus`) et option `clearInput={false}` pour les mots de passe.
- **Fond rouge des erreurs** : `V5State` en erreur avait une bordure `#b42318`. Remplacée par un contour encre et une icône.
- **Lint `react-hooks/refs`** : un drapeau `touched` en `useRef` lu pendant le rendu. Remplacé par un état.
- **Pièges de test (pas des bugs de l'app)** : les boutons d'`IonSegment` ont le rôle `tab` et l'hôte `ion-segment-button` intercepte le clic → cliquer `ion-segment-button` filtré par texte ; rouvrir une feuille d'actions pendant l'animation de fermeture de la précédente détachait le bouton → attendre qu'aucune `ion-action-sheet` ne reste ; le spinner caché de l'`IonRefresher` était compté → filtrer `ion-spinner:visible` ; le contrôle « pas de rouge » visait toute la page et trouvait les commandes de suppression (rouge légitime) → limité aux zones d'erreur et au toast.
- **Outils** : pas de .NET dans le conteneur → SDK 10.0.401 installé localement avec `dotnet-install.sh` ; une config Playwright placée hors du projet ne trouvait pas `@playwright/test` → config Chromium locale `SportTracker.Web/pw.local.config.ts`, exclue via `.git/info/exclude` (non commitée) ; Pillow installé pour les planches de comparaison.

## Apprentissages
- **`IonRouterOutlet` et la route sans `path`** : Ionic cherche d'abord une route qui correspond ; s'il n'en trouve aucune, il prend la route sans `path` (ni `from`). C'est le bon emplacement pour une page 404, même si l'outlet retient sinon la dernière route qui correspond.
- **EF Core `Update` sur un graphe** : il ajoute ou modifie les entités présentes, il ne supprime jamais les enfants absents. Pour une sémantique « remplacer la collection », supprimer explicitement ; `context.Remove(new Entité { Id = x })` suffit après `ChangeTracker.Clear()`.
- **Grille CSS et texte `nowrap`** : une piste implicite (`auto`) prend la largeur min-content de son contenu ; un texte non coupé peut faire déborder toute la page. `grid-template-columns: minmax(0, 1fr)` borne la piste.
- **Sauvegarde différée sur iPhone** : iOS peut tuer une PWA en arrière-plan sans autre événement ; toute écriture différée doit être vidée sur `visibilitychange` (caché) et `pagehide`.
- **Barre d'en-tête en grille à trois colonnes** : un élément caché par opacité garde sa place ; le réduire à largeur nulle quand il est caché.
- **Playwright + Ionic** : cliquer l'hôte `ion-segment-button` ; attendre la fin d'une feuille d'actions avant d'en ouvrir une autre ; les éléments masqués d'Ionic (spinner du rafraîchissement) restent dans le DOM.
- **Environnement cloud** : `dotnet-install.sh --channel 10.0 --install-dir …` installe un SDK utilisable sans droits système ; une config Playwright doit être dans le dossier du projet pour résoudre ses modules.
